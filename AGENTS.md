# Project context

Soundfolk's static website (GitHub Pages): plain HTML, CSS and JavaScript modules, pages generated by
`scripts/build.py` (Python 3.12, Pillow for the preview images); strict CSP, no framework, no third-party script.

## Verification commands

- Targeted test: `node --test scripts/test_link.mjs`
- Full suite: `npm test`
- Lint / format: none (`.prettierrc.json` sets the style, but Prettier is not a dependency)
- Typecheck: none
- Build without network: `python3 scripts/build.py --offline -o _site`

## Rules

- If the need or an edge case is ambiguous, ask 2 or 3 short questions before coding. Otherwise, go ahead.
- For any new logic or bug fix in the link reader: first write a failing test, then the minimal code that
  makes it pass.
- Touch only the files you need. No new dependency without asking.
- Never read, print or commit secrets or `.env` files.

## Pitfalls and non-obvious decisions

- `site/assets/link.js` reads links like the app's `src-tauri/src/share.rs` (soundfolk repository): change
  both together.
- The build writes nothing to the repository: the ids of lists ever built come back from the published
  `/lists-seen.txt`.

## Definition of done

Targeted tests and the affected suite green, offline build passing, no debug log and no off-topic change.
